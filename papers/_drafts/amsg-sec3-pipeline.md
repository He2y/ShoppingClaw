## 3.5 陌生 App 的五阶段建图管线

前述运行时检索（3.3 节）与在线学习（3.4 节）均以"图谱中已有可用边"为前提，而在线学习又以任务成功为写入条件——在一个图谱从未见过的 App 上，Agent 缺乏空间先验、任务成功率低，由此形成冷启动的循环依赖。本节给出 AMSG 的离线建图管线（对应贡献④）：一条"引导→探索→规范化→审核→入图"的五阶段闭环，将陌生 App 从零图谱推进到核心链路以 hypothesis 边入图的状态。区别于现有工作中一次性的数据集工程（如 KG-RAG 依赖 xTester 离线爬取、WebNavigator 依赖自适应 BFS），该管线是一套可对任意同域 App 重复执行的流程，且其产物与在线学习共用同一套生命周期消费机制。

管线的全部设计服从两条原则。**原则一：逃逸不依赖 VLM 分类正确。** 真实 App 环境高度干扰——直播间、抽奖弹窗、外跳页随时可能吞没探索进程，而此时恰恰是分类器最容易出错的时刻；因此所有逃逸与防御机制必须建立在机械信号之上（截图感知哈希、覆盖进度、前台包名等），分类结果只作参考。**原则二：离线探索产物一律不直写正式图谱。** 探索数据缺乏在线执行那样的"任务成功"质量门，人工审核因而成为离线数据进入图谱前的唯一质量门。整体流程如图 5 所示。

### 3.5.1 阶段一：App 引导（onboarding）

引导阶段对陌生 App 做安全采样：启动、按 Back、下滑各截取一张截图，全程绝不点击，从源头排除误触风险。强 VLM 据此推断 App 所属领域，产出 **draft profile**（`schemas/apps/<id>.yaml`），内容包括：domain 到领域模式的映射、覆盖建议、该 App 界面语言下的危险词与陷阱词（直播、抽奖、领券类入口）、登录墙标记与建议探索任务。VLM 输出随后经过一个确定性校验层对齐到领域模式（3.2 节）：覆盖类型经别名规范化并剔除干扰类型，越出模式的转移直接丢弃，与购物 CTA 冲突的"危险词"被降级——例如"加入购物车"在购物域是打开规格弹窗的入口而非危险动作，VLM 的保守判断需要被结构先验纠正。最后设人工确认门：draft 状态的 profile 允许驱动探索，但其产物被拒绝入图，人工核对后改为 confirmed 方可解锁。

### 3.5.2 阶段二：分轮焦点探索

探索阶段是管线的核心，其设计源于一项真机观察：小 GUI 模型（如 autoglm-phone-9b）能将"点击右上角的筛选按钮"精确 ground 到坐标，却不知道覆盖 `search_result→filter_panel` 这一目标*需要*去点筛选按钮——它没有规划能力，自主探索时永远在记忆中的主链路上打转。该观察直接导出**规划-执行分离**的架构：强 VLM 规划器每步接收当前截图、剩余焦点转移与最近执行结果，输出一条具体指令（如"点击右上角的'筛选'按钮"）；GUI 模型只接收这一条指令做 grounding 执行，完全看不到宏大的探索任务。执行结果回灌规划器（"指令 X 落到 search_result，预期 filter_panel 未达成"），失败则换打法，目标覆盖完毕则主动 finish。两个模型各自只做擅长的事：规划归强 VLM，落点归 GUI 模型。

单轮预算有限（每轮 24 步，设计参数），不可能覆盖全部目标，因此探索按**分轮焦点**组织：每轮启动时扫描历届产物的覆盖记录，从缺口中取一个小目标（骨架转移优先），完成即收尾保存，下一轮自动选取下一批缺口。焦点参数 `--focus` 支持结构化形式（`search_result->filter_panel`）与自然语言形式（"探索首页的秒送模块"）混用——后者没有预设转移，由规划器自主发现并判断结束。轮末由强 VLM 生成 round_summary（完成了什么、卡在哪、下轮建议）写入产物，作为跨轮规划的记忆。

探索全程由一个遵循原则一的防御栈守护，其"威胁→机械信号防御"对应关系如表 1 所示。

**表 1 探索防御栈：威胁与机械信号防御**

| 威胁 | 防御（不依赖分类正确性） |
|---|---|
| 直播间/广告页死循环 | 感知哈希滞留检测，逃逸逐级升级（Back→Back→重启 App）；陷阱词进入前拦截并回写踩坑负记忆 |
| 外跳浏览器/其他 App | 前台包名漂移检测，自动拉回目标 App |
| 弹窗/挽留弹窗 | 消解循环（找关闭按钮→Back→点空白）；Back 被拦截时寻找"退出/离开"语义按钮 |
| 人机验证（captcha） | 列为一等页面类型；默认蜂鸣暂停、人工接力完成后续跑；人工操作不记边 |
| 登录墙 | `--pause-on-login` 人工接力 |
| 加载中间帧被当作页面 | 落页稳定性检测：连续截图相似才送分类 |
| 分类器误判 | 三信号一致性核验（分类器输出/推理证据/landmark 结构）：不一致者按 transient 拒绝或标记 low_confidence 交审核 |
| 中断/崩溃 | 中断安全保存，已采集数据永不丢失 |

其中两项值得强调：captcha 不是异常而是一等页面类型——用 Back 绕开只是推迟问题，默认策略是蜂鸣暂停交人工接力，且人工操作期间不记录任何边，避免把人类的操作知识误标为模型可复现的转移；三信号一致性则把"单分类器判断"升级为交叉验证，分类结果须与推理证据及 landmark 结构核验一致，否则降级处理——这与原则一一脉相承：分类器只是证据之一，不是裁决者。

### 3.5.3 阶段三：staging 规范化

每轮探索产物（pages、transitions、轨迹 JSON 与截图证据）自动打包为 staging 批次（`memory_db/staging/<batch>/`）。规范化流程对候选数据做五项处理：基于语义签名（3.2 节）的去重、瞬态页过滤、Type+Submit 搜索宏合成、同页动作压缩、高风险边界过滤。关键约束是：staging 只在磁盘上组织候选，**不接触 Neo4j**——这是原则二在数据通路上的实现，正式图谱在此阶段对探索产物完全不可见。

### 3.5.4 阶段四：人工审核门

staging 批次经 Gradio 审核界面逐条人工裁决。每条候选边呈现：转移前后截图对、动作描述、观测次数与置信度、VLM 预判，以及**双盲交叉验证**结果——强 VLM 独立重新分类转移两端截图，且不被告知探索时的标签，与探索期标签不一致的候选标红置顶。批次概览呈现完整漏斗：探索记录 N 条、探索期被拒 K 条、进入候选 M 条、当前 approve/reject 统计——任何一条数据的去向都可追溯，不存在静默丢失。为降低审核负担，系统提供决策预填规则：VLM 批准、或观测不少于 2 次且非低置信、或来自人工辅助采集（操作者已亲眼验证两端）的候选预填 approve，其余预填 reject；预填仅是建议，最终裁决权在人。

### 3.5.5 阶段五：批准入图

`apply_review()` 将批准的边经 `promote_staging_to_canonical()` 写入 Neo4j，写入时携带 `lifecycle_stage="hypothesis"` 与溯源属性（`source_type=exploration_reviewed`、`review_batch_id`）。这里重申 3.4 节的不变量：**人工批准不豁免在线验证**——hypothesis 边对运行时 Agent 不可见，仍须经延迟后条件验证积累统计证据后方能提升为 promoted。换言之，人工审核回答的是"这条转移是否真实存在"，在线验证回答的是"它是否可靠到值得执行"，两个问题不可互相替代。此外，重复 apply 由 applied.json 回执拦截，保证批次写入的幂等性。

**人工辅助采集。** 当自主探索对某些转移无能为力（执行知识缺失）时，操作者或更强的 Agent 可直接驱动设备采集，产物按同一格式落盘，走同一条 staging→审核→入图管线，仅以 `source_kind=human_assisted` 标记来源。这是给图谱注入"转移→操作"执行知识的捷径：入图后探索器与运行时 Agent 即可复用，且因其经过同一审核门与同一在线验证，不构成质量上的特权通道。

### 3.5.6 与在线学习的衔接

离线管线解决的是冷启动；图谱最主要的持续数据来源仍是 3.4 节的在线学习——每次成功任务都可能发现新转移或验证已有转移。两条供给线的质量门相互独立（离线靠人工审核门，在线靠任务成功门与 VLM 轨迹审核），但汇入同一套生命周期消费机制：无论来源如何，所有边都从 hypothesis 起步，靠真实执行统计赢得 promoted 地位。这一管线的可复制性已有定性佐证：京东（含秒送外卖链路）从零图谱到核心链路入图即按此五阶段流程完成；探索期间经开放词表机制（3.2 节）浮出的即时零售页面类型提案，在人工审核合入领域模式后反哺整个购物域——后续同域 App 无需任何代码改动即可正确分类同类页面。至此方法各部分完整，下一章给出实验设计。

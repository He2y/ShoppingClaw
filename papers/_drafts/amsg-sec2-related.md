# 2 相关工作

本章按四条主线回顾相关工作：移动 GUI 智能体的总体谱系（§2.1）、图谱与结构化记忆驱动的导航方法（§2.2，与本文最直接相关）、智能体经验复用与记忆机制（§2.3），以及 GUI 智能体评测体系（§2.4）。每条主线末尾给出与本文工作的关联评述。

## 2.1 移动 GUI 智能体

移动 GUI 智能体研究大体沿两条路线演进。**框架路线**以通用 LLM/VLM 为底座，靠外围工程结构补足能力：[AppAgent, CHI 2025] 通过自主探索与人类演示为每个应用构建元素级知识文档，部署期查阅文档执行任务；[Mobile-Agent, arXiv 2024] 以 OCR 与检测定位实现纯视觉感知，摆脱对系统 XML 元数据的依赖；[Mobile-Agent-v2, NeurIPS 2024] 进一步引入规划、决策、反思三智能体协作与任务内记忆单元，缓解长程导航中的历史漂移。这一路线的共性局限在于：知识载体多为非结构化文本或仅在单任务生命周期内有效的记忆，缺少对应用状态空间的持久化结构建模。

**基座模型路线**则直接训练 GUI 专用的视觉语言模型：[CogAgent, CVPR 2024] 以双分辨率编码器支持高分辨率界面元素识别；[UI-TARS, arXiv 2025] 将统一动作空间与 System-2 式反思内化于端到端模型；[AutoGLM, arXiv 2024] 以中间接口分离规划与定位，并采用自进化在线课程强化学习；[Mobile-Agent-v3/GUI-Owl, arXiv 2025] 通过大规模后训练与云端虚拟环境自进化，在 AndroidWorld 上取得领先成绩。此外亦有以验证器替代生成器的尝试，如 [V-Droid, arXiv 2025] 让 LLM 对动作候选打分。

**评述**：基座路线依赖大规模后训练提升能力，数据与算力成本高，且能力提升内化于参数、难以审计与增量修正；框架路线的外围知识又普遍缺少结构与可靠性度量。本文不修改模型参数，而以外置的结构化页面-动作图谱在推理期增强小型 GUI 模型，与基座模型路线正交、可叠加于任意执行器之上。

## 2.2 图谱与结构化记忆驱动的导航

将环境结构显式建模为图谱以辅助导航，是与本文最接近的研究方向。本小节逐一辨析最近邻的四项工作及两项早期代表。需要说明的是，以下对各方法机制的概括基于其公开论文描述与公开实现，细节以原始文献为准。

**[PG-Agent, ACM MM 2025]** 提出自动管线将顺序执行轨迹转化为页面图——经页面跳转判定、节点相似性检查与图更新三步构图——并以 RAG 检索图中的感知指南辅助多智能体执行。其"页面天然成图、线性轨迹是图上路径采样"的直觉与本文一致，是本文承认并继承的起点。但据其论文描述，该页面图为离线一次性构建、在线只读：应用界面更新后边失效而系统不自知，新页面亦无法写回；图中所有边同等对待，仅记录"可达"而不记录"以多大概率可达"；图谱仅作为检索源改善提示内容，VLM 仍需每步推理，并不减少模型调用。

**[KG-RAG, EMNLP 2025]** 将不完整的 UI 转移图（UTG）经 LLM 离线图搜索转化为结构化向量库，在线以 embedding 检索导航路径辅助决策。这一"图谱向量化"路径在检索效率上有优势，但离线扁平化不可避免地损失拓扑结构——检索返回的是文本化路径片段而非可在其上继续推理的图；向量库构建后冻结，同样不追踪边的执行可靠性，也没有对"动作是否真的到达预期页面"的验证环节。

**[WebNavigator, arXiv 2026]** 走向另一个极端：其 Retrieve-Reason-Teleport 范式让离线构建的网站交互图直接控制跨页导航，VLM 只负责页面内操作，并据其论文报告随探索深度增加显著提升成功率。然而 Teleport 隐含"图谱总是正确"的假设——边因站点改版失效时缺少回退机制。更根本地，该方法面向可大规模廉价爬取的 Web 环境；移动应用受登录墙、风控与真机操作成本约束，无法以爬取方式获得高覆盖图谱，其构图前提在移动场景下不成立。

**[MobiAgent, arXiv 2025]** 与其加速框架 [AgentRR, arXiv 2025] 将经典 record-replay 引入智能体：记录交互轨迹并抽象为多级经验（ActTree 结构），重放时由二元匹配模型判断经验是否适用。据其公开描述，"可复用与否"是一次性的二元判断而非边级的连续可靠性度量；经验失效后的更新依赖手动纠正轨迹，亦无对重放结果的后条件验证。

更早的 **[AutoDroid, MobiCom 2024]** 以随机探索构建 UTG 并将探索记忆以文本注入 LLM，但其图谱来自与任务语义解耦的离线随机探索；**[MobileGPT, MobiCom 2024]** 将记忆组织为屏幕—子任务—任务的层级树并支持四阶段复用，但树结构难以容纳跨页面环路与多路径，且依赖 XML 视图层级，对纯视觉输入的智能体不适用。

表 1 从九个维度对比上述最近邻方法与本文提出的 AMSG。

**表 1 图谱驱动导航方法的逐维度对比**

| 维度 | PG-Agent | KG-RAG | WebNavigator | MobiAgent | AMSG（本文） |
|---|---|---|---|---|---|
| 图谱来源 | episode 批量离线构建 | 工具爬取 UTG | 自适应 BFS 爬取 | 任务执行记录 | 引导式探索 + 人工审核 + 在线学习 |
| 图谱更新 | 不更新 | 不更新 | 不更新 | 手动纠正轨迹 | 每次成功任务自动更新 |
| 边可靠性 | 不追踪 | 不追踪 | 哈希去重，无统计 | 二元匹配，不追踪 | 成功率追踪 + 四阶段生命周期 |
| 图谱/VLM 边界 | RAG，VLM 每步推理 | 同左 | Teleport，无回退 | 二元重放 | 逐边独立判定（锚定→图谱 / 非锚定→VLM） |
| 噪声控制 | 双层相似度 | 图搜索评分 | DOM 差分 | 无 | 四道质量门（任务成功 + VLM 审核 + 规范化 + 人工审核） |
| 后条件验证 | 无 | 无 | 无 | 无 | t+1 延迟验证，统计基于真实观测 |
| 自修复 | 无 | 无 | 无 | 无 | 成功率下降→自动降级→重新探索 |
| 跨 App 泛化 | 单 App | 单 App | 单站点 | 单 App | 域模式先验 + 开放词表进化 |
| 探索规划 | — | 爬虫 | BFS | — | 强 VLM 规划 / GUI 模型执行分离 |

**评述**：综观表 1，现有图谱方法在三个维度上集体空缺。其一是**活性**：四者的图谱均在构建后冻结或仅靠人工维护，无法跟随应用的持续更新自我演化；其二是**可靠性度量**：边一律是布尔存在性，同一动作的多种结果（登录拦截、A/B 弹窗）被无差别存入，规划器可能选中仅在特定条件下成立的路径；其三是**控制边界**：图谱与模型的分工要么"永远 RAG"（不节省模型调用），要么"永远 Teleport"（无失效回退），缺少逐转移粒度的边界判定。尤为关键的是，四者均无后条件验证——系统记录的是"智能体以为会到达哪里"而非"实际到达了哪里"，即便引入可靠性统计也缺乏事实根基。本文以在线学习与生命周期管理的活图谱、边级成功率追踪，以及锚定性驱动的逐边控制边界回应这三重空缺，并以 t+1 延迟后条件验证为全部统计提供真实性基础。

## 2.3 经验复用与记忆机制

更一般的智能体经验复用研究为本文提供了另一参照系。[AWM, arXiv 2024] 从历史轨迹归纳可复用 workflow；[Synapse, ICLR 2024] 以状态抽象后的完整轨迹作为 few-shot 范例并按相似度检索；[ExpeL, AAAI 2024] 将经验提炼为自然语言 insight 在推理期召回；[Voyager, TMLR 2024] 开创以可执行代码为技能单元的技能库路线；在移动场景中，[Mobile-Agent-E, arXiv 2025] 以 Tips 与 Shortcuts 两类扁平条目实现长期记忆自进化，[AppAgentX, arXiv 2025] 则从重复轨迹中抽象高阶动作以压缩执行步数。

**评述**：上述方法的复用单元——workflow、轨迹范例、语言规则、代码技能、扁平条目——本质上都是线性序列或无结构条目，其共同上限在于复用以"存在一条整体相似的历史经验"为前提：新任务若与任何历史轨迹整条都不相似，即无经验可用。本文将多条轨迹融合进同一全局图谱，复用粒度降至边与子路径——新任务可以走一条从未整条出现过、但每段都被独立验证过的组合路径，从而把经验复用从"轨迹匹配"提升为"图上规划"。

## 2.4 GUI 智能体评测

评测体系方面，[AitW, NeurIPS 2023] 以 71 万余条人类演示建立了离线动作匹配评测的事实标准，但静态匹配无法度量真实环境中的闭环成功率；[AndroidWorld, arXiv 2024] 提供可参数化任务与系统状态奖励信号的在线 Android 环境，是当前最主流的在线基准，但任务集中于开源与系统应用；[AndroidLab, ACL 2025] 在统一动作空间下支持 LLM 与多模态模型的可复现评测，也是本文执行器所属模型体系的训练评测环境；[SPA-Bench, arXiv 2024] 覆盖 340 个中英文真实第三方应用任务并引入成本、耗时等多维指标；[ScreenSpot-Pro, ACM MM 2025] 则显示当前最强模型在高分辨率专业界面上的元素定位准确率仍然很低，直接支撑了本文"小模型 grounding 远未解决、需要系统级结构兜底"的动机。

**评述**：现有基准或为离线静态匹配，或集中于干扰较少的开源应用，普遍缺少中文电商类高干扰、多约束、长程导航任务——而这恰是图谱式导航记忆价值最大的场景。这一空缺构成本文第 4 章在真实商业应用上自建真机评测的依据。

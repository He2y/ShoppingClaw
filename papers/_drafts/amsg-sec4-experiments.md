# 4 实验

本章给出 AMSG 的评测框架。实验设计的核心原则是"研究问题与创新主张一一对应"：第 1 章提出的三项核心创新（活图谱、边级可靠性与生命周期、锚定性控制边界）连同跨 App 泛化能力，分别由四个研究问题（RQ1–RQ4）承载，并通过基线对照与消融开关矩阵逐项验证。需要说明的是，设计文档中给出的延迟与调用次数数字（如快速路径 ~0.5s、VLM 路径 ~5s、不同成熟阶段的端到端延迟）均为实测估算，仅用于陈述预期趋势，其有效性有待本章实验验证；本章全部量化结果以【实验数据待补充】占位。

## 4.1 研究问题

**RQ1（活性）**：在线学习与自动持久化机制相比静态冻结图谱，对任务成功率与跨任务效率的贡献有多大？具体包括两个子问题：(a) 随成功任务数增长，图谱覆盖率与快速路径命中率的演化曲线；(b) 在注入 UI 漂移（人为使若干 promoted 边失效）后，自修复闭环（统计偏移→降级→VLM 重探索→重新提升）恢复到漂移前性能所需的任务数。设计文档给出的"通常 3–5 次任务内恢复"为经验估计，有待验证。

**RQ2（可靠性度量）**：边级成功率追踪与四阶段生命周期（hypothesis→candidate→promoted→demoted）相比布尔存在性边，对错误快速路径执行率与规划质量的影响如何？布尔边将多结果转移（登录拦截、A/B 弹窗）一律视为有效转移，预期会产生不可靠的快速路径与误导性规划；生命周期机制以 t+1 延迟后条件验证为统计根基，仅放行统计达标的边。

**RQ3（控制边界）**：锚定性逐边调度相比两个极端——全 RAG（PG-Agent 式：图谱仅做提示注入，VLM 每步推理）[PG-Agent, ACM MM 2025] 与全 Teleport（WebNavigator 式：promoted 边一律直接重放）[WebNavigator, arXiv 2026]——在"成功率—端到端延迟—VLM 调用次数"三维权衡空间中处于什么位置？我们预期逐边调度能同时逼近全 RAG 的成功率与全 Teleport 的延迟，但该预期来自设计文档的实测估算趋势，有待验证。

**RQ4（泛化与冷启动）**：五阶段建图管线、同域结构先验与开放词表对陌生 App 冷启动各贡献多少？以京东（含秒送外卖链路）作为"陌生 App"场景，度量从零图谱到核心流程覆盖所需的探索轮次与人工审核成本。

各研究问题的总体结果见表 4-1【实验数据待补充】。

## 4.2 实验环境

评测采用真机 Android 在线评测而非离线步级匹配。如第 2.4 节所评述，AitW 类离线基准 [AitW, NeurIPS 2023] 以预录轨迹的动作匹配为指标，无法度量闭环任务成功率，也无法体现弹窗、广告、A/B 测试等真实干扰下的导航鲁棒性，而后者正是 AMSG 针对的问题域。

目标 App 为两个真实中文电商应用：淘宝（核心购物流程）与京东（核心流程及秒送外卖链路）。执行模型为 autoglm-phone-9b 类小型 GUI 模型；强 VLM（经 `AMSG_STRONG_VLM_MODEL` 配置）仅用于轨迹审核与探索规划，不参与在线逐步执行。任务集为中文电商长程任务，覆盖多条件筛选、价格区间约束与规格选择三类约束组合，完整任务清单与难度分布见附录【实验数据待补充】。实验环境配置（设备型号、系统版本、Neo4j 版本、网络条件）见表 4-2【实验数据待补充】。

## 4.3 基线

我们对比四个系统：① **纯 VLM 无图谱**：每步完整 VLM 推理，无任何图谱辅助，代表无记忆的下界；② **静态图谱 + RAG**（PG-Agent 式协议）：图谱构建完成后冻结、在线只读，图谱知识仅作为提示注入，VLM 仍每步推理；③ **静态图谱 + 直接重放**（WebNavigator/Teleport 式协议）：promoted 边一律直接执行，无生命周期、无降级回退；④ **AMSG 完整系统**。

需要注明，基线②③并非原系统的直接运行，而是在本框架内对其控制协议的复刻实现（re-implementation）：复用相同的感知、动作执行与图谱存储基础设施，仅替换图谱的更新策略与调度策略，以保证差异完全归因于控制协议本身而非工程实现细节。各基线在统一任务集上的对比结果见表 4-1【实验数据待补充】。

## 4.4 评价指标

指标分四组。**任务级**：任务成功率、平均步数、端到端延迟、每任务 VLM 调用次数。**图谱级**：快速路径命中率（快速路径执行步数占比）、promoted 边精确率（即错误快速路径执行率的补，度量生命周期门控质量）、图谱覆盖率增长曲线（覆盖的页面类型与转移占域模式覆盖目标的比例，随任务数演化）。**鲁棒性**：UI 漂移注入后恢复所需任务数（对应 RQ1b）。**建图成本**：五阶段管线的人工审核漏斗通过率（探索候选→审核批准→在线提升各环节的转化率，对应 RQ4）。各指标定义与测量方法的形式化描述及结果见表 4-3【实验数据待补充】。

消融实验完全基于系统已实现的运行时开关（源自设计文档第 8 节），无需修改代码即可复现。表 4-4 给出完整矩阵。

| (a) 建图管线 | `build_fast_prompt(open_vocab=False)` | 封闭词表分类（"泛化失败"基线） | RQ4 |
| (a) 建图管线 | `AMSG_DOMAIN_PRIORS=0` | 无同域结构先验的冷启动对照 | RQ4 |
| (a) 建图管线 | `--no-staging` / `--no-human` | 关闭 staging 自动打包 / 人工接力 | RQ4 |

| (c) 核心消融 | 去生命周期（所有边即 promoted，可用 legacy 近似） | 验证可靠性追踪的价值 | RQ2 |
| (c) 核心消融 | 去锚定分类（全 VLM / 全快速两个退化端） | 验证逐边控制边界的价值 | RQ3 |
| (c) 核心消融 | 去后条件验证 | 验证统计真实性根基的价值 | RQ2 |
| (c) 核心消融 | 去域先验 + 封闭词表 | 验证跨 App 泛化机制的价值 | RQ4 |
| (d) 默认关闭扩展 | 多通道信念定位 / Belief-A* / 熵驱动验证边界 | 附加消融候选 | — |

关于 (b) 需注明一处实现约束：离线建图管线（staging 与审核入图）固定使用 plausibility 策略——`sava` 预设的 verified 边策略要求运行时后条件记录，对离线探索数据会过滤掉全部候选，故 `AMSG_CONFIG` 各预设的对比只在在线学习链路上有意义，离线数据的质量门始终是人工审核。

(c) 组核心四消融与本文四项主张一一对应：去生命周期与去后条件验证共同回答 RQ2（后者进一步检验"成功率统计必须以实际到达页面而非预期到达页面为事实来源"这一根基性主张）；去锚定分类的两个退化端恰好对应 4.3 节基线②③的调度策略，回答 RQ3；去域先验与封闭词表回答 RQ4。

(d) 组为已实现但默认关闭的扩展（多通道贝叶斯信念定位、Belief-A* 规划、熵驱动 VLM 验证边界）。其默认关闭的理由是内部观察显示在当前图谱规模（不足 50 节点）下增强项贡献甚微，这一观察本身不构成消融结论；它们在更大图谱规模下的效果列为附加消融候选，结果【实验数据待补充】。
